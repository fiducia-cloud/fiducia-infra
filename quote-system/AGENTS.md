# AGENTS.md — Fiducia quote system

These instructions apply to `quote-system/**` and supplement the repository-root instructions. The stricter rule wins.

## Trust and ownership boundaries

- This directory defines Fiducia-specific commercial intake and infrastructure contracts. Concrete Fiducia Cloudflare zones, hostnames, routes, origins, account/zone identifiers, WAF policies, and encrypted deployment values belong in `fiducia-cloud/fiducia-infra`.
- Reusable Cloudflare modules may be imported from `ORESoftware/cloudflare-infra`, but they must remain parameterized. Never copy a real Fiducia binding into the shared repository.
- Do not guess the zone apex. Use `${FIDUCIA_ZONE_APEX}` and reviewed environment inputs until the owning zone is explicitly confirmed.
- Never activate DNS, Workers, databases, contracts, quotes, or signature providers from a documentation/schema pull request.

## Credentials, PII, and legal/commercial data

- Never commit plaintext credentials, Age identities, access tokens, customer data, signatures, contract bodies, raw IP addresses, raw user agents, or production organization/contact values.
- Example files must use reserved example domains and visibly synthetic values.
- Sensitive organization, contact, application, attachment-object, contract-object, and outbox payload fields are application-layer ciphertext before persistence.
- Logs, traces, metrics, errors, issue comments, and pull-request descriptions contain opaque identifiers, hashes, reason codes, and bounded metadata only.
- Credential material disclosed in chat or Git history is treated as exposed. Do not copy, test, rotate, revoke, or migrate it; only an authorized owner performs credential lifecycle actions.

## Interface and schema policy

- TypeSpec and JSON Schema Draft 2020-12 are complementary and both remain canonical:
  - TypeSpec owns HTTP operations, cross-language generation, and transport-facing models.
  - JSON Schema owns portable payload validation, fixtures, and compatibility checks.
- Protobuf may be added for trusted internal transport but does not replace the TypeSpec/JSON Schema public boundary.
- Rust services map persistence through Diesel and/or SeaORM. Do not encode PostgreSQL rows directly as public API payloads.
- All public identifiers are opaque, non-sequential, bounded strings generated by the application. Never expose database sequences.
- Every write/transition operation requires an idempotency key. Every update/transition requires an optimistic version or `If-Match` precondition.
- Public and administrative APIs use distinct route namespaces, authentication audiences, and authorization policies.

## Tenant and provenance rules

- Every customer-owned record includes `tenant_id` and is protected by forced PostgreSQL row-level security. An unset tenant context must match no tenant rows.
- Application, quote, support-plan, SLA-policy, contract-template, acceptance, line-item, contract-reference, and workflow-event evidence is append-only.
- Corrections create a higher immutable version with `supersedes_version`; accepted/issued documents bind exact content hashes.
- Contract acceptance binds the signer authority attestation, exact quote ID/version/hash, exact contract references/hashes, signature evidence, and hashed request metadata.
- Internal SLOs and customer-facing contractual SLAs are separate versioned objects.

## State-machine rules

- The allowed commercial lifecycle is defined once in `contracts/commercial-intake.schema.json` and must exactly match `db/0001_commercial_intake.sql`.
- Terminal states have no outgoing transitions.
- New transitions require a reason code, actor identity hash, request ID, idempotency-key hash, prior/resulting version, and append-only audit event.
- Do not add shortcuts around email verification, qualification, security review, pricing approval, legal/procurement, signing, or provisioning without an explicit reviewed policy change and tests.

## Pricing, SLA, and support rules

- Money uses integer minor units plus ISO-style three-letter currency codes. Never use binary floating point for persisted amounts.
- Quote totals satisfy `subtotal - discount + tax = total`; line-item quantity and unit-price arithmetic must reconcile with the subtotal.
- Quote versions bind exact support-plan and SLA-policy IDs, versions, and hashes.
- P1 through P4 definitions and response/update/mitigation/restoration targets are complete and monotonic.
- SLA service-credit thresholds worsen monotonically while credit percentages increase monotonically and never exceed the documented cap.

## Required verification

For every change beneath this directory:

```bash
python3 -m py_compile quote-system/tests/test_contracts.py
python3 -m unittest -v quote-system/tests/test_contracts.py
```

Database changes additionally run the isolated PostgreSQL migration and `quote-system/tests/test_postgres_contract.sql`, then reapply the migration to verify guarded DDL.

A pull request remains draft until exact-head CI is visible and passing. Schema presence alone is not proof that DNS, APIs, UIs, database migrations, or customer workflows are deployed.
